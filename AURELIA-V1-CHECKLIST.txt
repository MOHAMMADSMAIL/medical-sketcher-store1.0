### 4. أهم Flow لازم الـ AI يفحصه

```mermaid
sequenceDiagram
    participant U as User
    participant W as Next.js
    participant A as NestJS API
    participant DB as PostgreSQL
    participant P as Payment
    participant S as Storage
    participant E as Email

    U->>W: Login
    W->>A: POST /auth/login
    A->>DB: Verify User
    DB-->>A: User
    A-->>W: HTTP-only Session Cookie

    U->>W: Browse Books
    W->>A: GET /products
    A->>DB: Query Products
    DB-->>A: Products
    A-->>W: Products

    U->>W: Add Book to Cart
    W->>A: POST /cart/items
    A->>DB: Cart + CartItem
    DB-->>A: Updated Cart
    A-->>W: Cart

    U->>W: Checkout
    W->>A: POST /orders
    A->>DB: Validate Cart + Product Prices
    DB-->>A: Valid Cart
    A->>P: Create Payment
    P-->>A: Payment Result

    alt Payment Success
        A->>DB: Mark Order PAID
        A->>DB: Create DownloadPermission
        A->>DB: Add Library Access
        A->>E: Send Purchase Email
        A-->>W: Order Success
    else Payment Failed
        A->>DB: Keep Order Unpaid
        A-->>W: Payment Failed
    end

    U->>W: Open Library
    W->>A: GET /library
    A->>DB: Verify Purchase
    DB-->>A: Authorized Books
    A-->>W: Library

    U->>W: Download Book
    W->>A: GET /downloads/:id
    A->>DB: Verify Permission
    DB-->>A: Permission Valid
    A->>S: Request Protected File
    S-->>A: Temporary URL
    A-->>W: Secure Download
```

**النقطة المهمة:** الـ UML فوق مش مجرد رسم شكلي؛ خلي الـ AI يعتبره **Contract** للمشروع. أي سهم في الرسم لازم يقدر يثبت له من الكود أن الاتصال موجود فعلياً، وليس فقط أن أسماء الـ modules موجودة.

إذا طلع مثلاً `DownloadsModule` موجود لكن ما في اتصال صحيح بين `Payment → DownloadPermission → Storage`، النتيجة لازم تكون **FAIL** وليس PASS.
